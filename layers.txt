Lambda Layer: openai-python312
================================

Why a layer?
  The Lambda Python runtime ships with boto3 but NOT with the `openai` SDK, so
  `from openai import OpenAI` fails with ImportModuleError. The SDK (and its
  dependencies: httpx, pydantic, pydantic_core, jiter, anyio, ...) is packaged
  as a Lambda Layer and attached to the function.

Layer details
  Name:                     openai-python312
  ARN:                      arn:aws:lambda:us-east-1:339713048675:layer:openai-python312:1
  Compatible runtime:       python3.12
  Compatible architecture:  x86_64
  ZIP file:                 layer/openai-layer.zip  (~6 MB)

How it was built  (script: layer/build_layer.sh)
  1. Install the package into a folder named `python/`. Lambda extracts layers
     to /opt and adds /opt/python to sys.path, so this folder name is required:

       pip install openai \
         --target build/python \
         --platform manylinux2014_x86_64 \
         --implementation cp \
         --python-version 3.12 \
         --only-binary=:all:

     The --platform / --python-version / --only-binary flags force Linux x86_64
     wheels. The build machine is an Apple Silicon Mac, and without these flags
     pip would install macOS arm64 binaries of pydantic_core / jiter, which
     crash on Lambda.

  2. Zip it so `python/` sits at the root of the archive:

       cd build && zip -r9 ../openai-layer.zip python

How it was published and attached
  3. Publish the layer:

       aws lambda publish-layer-version \
         --layer-name openai-python312 \
         --zip-file fileb://layer/openai-layer.zip \
         --compatible-runtimes python3.12 \
         --compatible-architectures x86_64

  4. Attach it to the function (in the console under Code -> Layers -> Add a
     layer -> Custom layers, or with the CLI):

       aws lambda update-function-configuration \
         --function-name open-ai-chatbot \
         --layers arn:aws:lambda:us-east-1:339713048675:layer:openai-python312:1
